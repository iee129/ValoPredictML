# 00. 공통 레이아웃 설계

> Streamlit 기반 — FastAPI/Next.js 사용 안 함
> 마지막 업데이트: 2026-05-04

---

## 0. 왜 Streamlit인가?

**왜 FastAPI + React/Next.js가 아닌 Streamlit을 쓰는가?**
FastAPI + React 구조는 백엔드 서버와 프론트엔드 앱을 별도로 개발하고 배포해야 한다. 이 프로젝트의 목적은 발로란트 라인업 분석 도구를 로컬에서 빠르게 실험하는 것이다. Streamlit은 Python 스크립트 하나로 UI를 만들 수 있어서 ML 코드와 UI 코드를 같은 파일에서 관리할 수 있다. 클라우드 배포, 외부 API 연동이 없는 로컬 분석 도구 용도에서는 Streamlit이 훨씬 적합하다.

**왜 승률만 보여주지 않고 원인과 변화량도 함께 표시하는가?**
"팀 A 승률 63%"만 나오면 사용자는 어떤 조합을 바꿔야 더 이길 수 있는지 알 수 없다. feature importance와 교체 변화량을 함께 보여줘야 "Controller를 추가하면 승률이 7% 오른다"는 실용적인 판단이 가능해진다. 이것이 이 프로젝트가 다른 단순 승률 예측 도구와 차별화되는 지점이다.

## 1. 공통 레이아웃

실제 구현(`app/main.py`)은 `st.tabs` 3탭 구조다. 사이드바 없음.

```
app/main.py
└── st.tabs(["커스텀 5v5", "경기 다시보기", "모델 근거"])
    ├── 탭 1: 커스텀 5v5 — 맵 선택 + 팀 A/B 요원 선택(폼) + 승률 결과
    ├── 탭 2: 경기 다시보기 — 실제 경기 재현 입력 + 예측 결과
    └── 탭 3: 모델 근거 — SHAP 피처 중요도, 모델 성능 지표
```

| 영역 | 역할 |
|------|------|
| 탭 1 (커스텀 5v5) | 맵·요원 조합 직접 입력, 승률·역할 분포 결과 |
| 탭 2 (경기 다시보기) | 실제 경기 데이터 재현 예측 |
| 탭 3 (모델 근거) | SHAP 기여도, 모델 성능 지표 요약 |
| 결과 영역 | 승률, 주요 영향 피처, confidence |
| 기록 | 예측 기록 영속화는 현재 미구현 (PostgreSQL/SQLite 범위 외) |

**화면 원칙**: 첫 화면(탭 1)에서 바로 조합 실험 가능. 승률만 표시하지 않고 원인과 변화량 함께 표시.

**Streamlit 컴포넌트 (실제 구현)**:

| 용도 | 컴포넌트 |
|------|----------|
| 화면 이동 | `st.tabs` (3탭: 커스텀 5v5 / 경기 다시보기 / 모델 근거) |
| 선수/요원 선택 | `st.multiselect`, `st.selectbox` |
| 수치 입력 | `st.number_input`, `st.data_editor` |
| 모델 실행 | `st.button` |
| 결과 카드 | `st.metric`, `st.columns` |
| 차트 | `st.bar_chart`, Plotly 후보 |
