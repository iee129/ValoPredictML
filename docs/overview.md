# 프로젝트 개요

ValoPredictML — Valorant 5v5 라인업 기반 승률 예측 Streamlit 로컬 분석 도구.

---

## 1. 정의 및 목표

**한 줄 정의**: 맵 + 선수 조합 + 요원 조합 입력 → 승리 확률 + 예측 근거 출력

> **라인업**: 선수 5명 + 각 선수의 요원 픽 전체. 이 프로젝트의 핵심 입력 단위.

| 항목 | 기준 |
|------|------|
| 제품 형태 | Streamlit 기반 로컬 분석 도구 |
| 핵심 흐름 | 조합 입력 → 승률 예측 → 영향 피처 확인 → 교체 시뮬레이션 |
| 현재 구현 | 데이터 수집, ML 파이프라인, Streamlit 로컬 UI, SQLite 예측 기록 |
| 진행 중 | P1-P4 57개 활성 피처 기준 산출물 재생성/검증 |
| 제외 | FastAPI, React/Next.js, 클라우드 배포, 외부 API — 사용 안 함 |

### 개발 원칙

1. 딥러닝(PyTorch, TensorFlow) 금지 — Tabular 데이터 기반 Tree-based 머신러닝만 사용
2. API Key 및 비밀번호는 `.env` 환경변수로 관리, GitHub 커밋 절대 금지

### 입력

| 구분 | 항목 |
|------|------|
| 사용자 입력 | 맵, 선수 5명 + 요원 5명 (팀당), 선공/후공 |
| 선택 입력 | 선수 정보 (ACS, K/D/A, KAST, ADR, 클러치율) |
| 시스템 생성 | 역할군 카운트/차이, map_encoded, Controller 여부, 팀 시너지 피처 |

### 출력 (Streamlit UI)

| 출력 | 설명 |
|------|------|
| 승리 확률 | 팀 A 승률 (이진 분류 확률값) |
| 주요 영향 피처 | feature importance 또는 SHAP |
| 선수-요원 적합도 | 특정 선수+요원 조합의 예상 기여도 |
| 교체 변화량 | 선수/요원 교체 전후 예측 확률 차이 |
| 맵별 최적 요원 조합 | 해당 맵에서 best인 요원 5명 도출 |
| 최정예 로스터 | 최고의 선수 조합, 키 플레이어 식별 |
| 맵 통계 | 요원 픽률, 요원별 승률, 공격/수비 유리도 시각화 |

## 2. 아키텍처

```
Kaggle 원천 데이터 (data/raw/kaggle/, 2.3GB)
        ↓
전처리 파이프라인 (ml/data_pipeline.py) ← 완료
        ↓
역할군 baseline 피처 (train/val/test)
        ↓
Random Forest / XGBoost / LightGBM 학습 → models/
        ↓
Streamlit 앱 → 입력 조합 예측 + 설명 + SQLite 기록
        ↓
SQLite 예측 기록 저장 (기본)
```

**목표 시스템 구조**:

```
┌─────────────────────────────────────┐
│  Streamlit UI (구현)                 │
│  - 선수/요원 조합 입력               │
│  - 예측 결과 + 영향도 시각화         │
└──────────────┬──────────────────────┘
               │ Python 함수 호출
               ↓
┌─────────────────────────────────────┐
│  모델 레이어 (완료)                   │
│  - Feature Builder                  │
│  - RF / XGBoost / LightGBM          │
│  - SHAP / feature importance        │
└──────────────┬──────────────────────┘
               │ SQLAlchemy (후보)
               ↓
┌─────────────────────────────────────┐
│  데이터 레이어                        │
│  - SQLite 예측 기록                  │
└─────────────────────────────────────┘
```

### 기술 스택

| 계층 | 기술 | 상태 |
|------|------|------|
| 언어 | Python 3.14.4 | 현재 구현 |
| 데이터 처리 | pandas, NumPy | 현재 구현 |
| UI | Streamlit | 구현 |
| ML | Random Forest, XGBoost, LightGBM | 완료 |
| 설명 | feature importance, SHAP | 완료 |

## 4. 차별점

기존 발로란트 통계 도구 및 ML 프로젝트와의 고유성:

| 차별점 | 기존 도구 / 프로젝트 | 이 프로젝트 |
|--------|---------------------|------------|
| **데이터 규모** | 최근 1~2시즌 스냅샷 | 2021~2026 6년치 + 6지역 핵심 데이터 약 300K+ 경기 (vct_2021_2023 1.2GB + ryanluong challengers 1.0GB + qualidea 249K행) |
| **선수-요원 적합도** | 요원 전체 승률만 제공 | `Team_Agent_Experience` — 특정 선수가 해당 요원을 과거에 플레이한 경험 횟수를 수치화, "좋은 요원을 숙련된 선수가 드는가"를 피처로 포착 |
| **공수 사이드 비대칭** | 정성적 설명 | `atk_side_advantage` — ryanluong challengers `Attacker Score`/`Defender Score`에서 맵별 공격 사이드 전역 승률을 직접 집계, 수치로 정량화 |
| **팀 시너지 정량화** | 개인 스탯 단순 평균 | FK/FD 비율 + 어시스트 + 누적 동반 출전 횟수(`Team_Shared_Exp`)로 팀 연계력을 수치화 |
| **출력 깊이** | 승률 수치 1개 | 승률 + 교체 delta(선수·요원 교체 전후 승률 변화량) + 최적 요원 조합(27종 중 5종 = 80,730가지 탐색) + 키 플레이어 기여도 |
| **예측 근거** | 없음 또는 단순 통계 | SHAP + feature importance로 "왜 이 팀이 유리한가" 피처 수준 설명 |
| **지역별 메타 반영** | 특정 지역·대회 편중 | Americas / EMEA / Pacific / China 4개 지역 데이터를 통합 학습 — 지역별 조합 스타일 차이를 모델이 학습 |

**핵심 가치**: "이 조합이 이길 확률은 얼마인가"에서 나아가 "어떤 피처 때문인가", "무엇을 바꾸면 얼마나 오르는가"까지 데이터로 설명하는 것.

## 5. 모델 전략


**메인 모델: 앙상블**

RF / XGBoost / LightGBM 세 모델의 예측 확률을 평균 내어 최종 승률 산출.

**왜 단일 모델이 아니라 앙상블을 쓰는가?**
모델마다 데이터를 분석하는 방식이 다르기 때문에 각자 잘 잡아내는 패턴도 다르다. 한 모델이 놓친 패턴을 다른 모델이 잡을 수 있다. 세 모델의 예측을 평균 내면, 한 모델이 특정 경기에서 크게 틀려도 나머지 두 모델이 균형을 잡아주기 때문에 단일 모델보다 안정적이고 정확한 예측이 나온다.

**앙상블 작동 방식**:
```
RF 예측     → 팀 A 승률 0.62
XGBoost 예측 → 팀 A 승률 0.58
LightGBM 예측 → 팀 A 승률 0.65

최종 승률 = (0.62 + 0.58 + 0.65) / 3 = 0.617
```

| 모델 | 선정 이유 |
|------|----------|
| Random Forest | 여러 결정 트리를 독립적으로 학습한 후 다수결로 예측 — 안정적인 baseline |
| XGBoost | 이전 트리의 오차를 다음 트리가 보정하며 반복 학습 — tabular 데이터에 강함 |
| LightGBM | XGBoost와 같은 방식이나 학습 속도가 빠르고 메모리 효율이 높음 |

---

**K-Fold 교차 검증**

**왜 그냥 train/val로 나누지 않고 K-Fold를 쓰는가?**
train/val을 한 번만 나누면, 우연히 val 데이터가 쉬운 경기들로 구성됐을 때 성능이 실제보다 좋게 나올 수 있다. K-Fold는 train 데이터를 K개 조각으로 나누고, 각 조각을 한 번씩 검증셋으로 사용하여 K번 학습·평가를 반복한다. K번의 결과를 평균하면 데이터 분할 방식에 따른 편차가 줄어들어 모델의 실제 일반화 성능을 더 신뢰할 수 있다.

**K-Fold 작동 방식** (K=5 예시):
```
train 데이터를 5조각으로 나눔:
  [조각1] [조각2] [조각3] [조각4] [조각5]

1회: [조각1]을 검증 → 나머지 4조각으로 학습 → Accuracy 기록
2회: [조각2]를 검증 → 나머지 4조각으로 학습 → Accuracy 기록
3회: [조각3]을 검증 → ...
4회: [조각4]를 검증 → ...
5회: [조각5]를 검증 → ...

최종 성능 = 5번 Accuracy의 평균
```

test.csv는 K-Fold와 완전히 분리 유지 — 최종 평가에만 한 번 사용.
